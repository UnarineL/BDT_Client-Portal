# Payment & Receipt v1

## What this adds

- Payments tab inside each client workspace.
- Upload proof of payment as PDF or image.
- PDF text extraction where the PDF contains selectable text.
- OCR for image proofs.
- Best-effort extraction of amount, date, reference, payer, bank and description.
- Human review before saving any payment record.
- Original proof stored privately in the existing `client-files` bucket under `payments/<submission-id>/...`.
- Unique receipt number generated by the database.
- Receipt PDF generation in the browser.
- `mailto:` helper for preparing a client email. The generated PDF must be attached manually.

## Supabase migration

Run the full `supabase-setup.sql` in Supabase SQL Editor. The script is designed to be safe to run again and adds the `public.payments` table and staff-only RLS policies.

## Important behavior

Extraction is advisory only. Staff must review and confirm the amount and payment date before the record is saved.

The browser performs PDF text extraction/OCR. No service-role key or AI provider secret is placed in the frontend.

## Current scope

This is not a full accounting system. It does not calculate tax, reconcile bank accounts, generate invoices, or automatically verify that a bank transfer occurred.
